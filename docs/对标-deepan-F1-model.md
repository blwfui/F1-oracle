## 六、根因定位：一行正则 + 一次上游静默变更

他的 `src/data_pipeline.py:163`（以及 `:258` 的重复分支）：

```python
# Add DNF flag: classified finishers include "Finished" and "+N Lap(s)"
merged["DNF"] = ~merged["Status"].str.match(r"^(Finished|\+\d+ Laps?)$", na=True)
...
merged.loc[merged["DNF"], "FinishPosition"] = 21
```

**注释的意图是对的，正则没实现它**：`Lapped` 永远匹配不上，于是每一个
「被套圈但已完赛」的车手都被打上 DNF，`FinishPosition` 被覆盖成 21。

### 为什么它曾经是对的

FastF1 在 2023 年改过 `Status` 的表示法 —— 这是我们用自己的库逐值核对出来的：

| 赛季 | 被套圈完赛者的 `Status` 写法 |
|---|---|
| 2018–2022 | `+1 Lap` / `+2 Laps` / `+N Laps` |
| **2023–2026** | **`Lapped`**（统一缩写） |

所以**写这段代码的时候它是正确的**，是上游一次静默变更让它失效了。
全库 **406 条 `Lapped` 条目全部被误判**，集中在 2023（70）、2024（138）、
2025（89）、2026（109）。他的 `test_years = [2020…2026]` 里，
**7 年有 4 年被污染**。

### 污染是三层，不只评估

1. **评估虚高** —— 就是第二节那张表：0.6898 → 0.6559（−0.034）
2. **训练标签被污染** —— `backtest.py:64` 的 `y = 21 - FinishPosition` 把
   「慢但跑完了」和「退赛」赋成同一个标签 0。排序器被教成
   **"被套圈 = 等于退赛"**
3. **DNF 派生特征被污染** —— `driver_dnf_rate` 与 `constructor_reliability`
   都由同一个 `DNF` 旗标算出，2023 年后的 DNF 计数被系统性高估

### 修法：其实不必修正则

FastF1 的 `session.results` 里有官方字段 `ClassifiedPosition`，
它天生就是这个语义（已实测 2018 / 2021 / 2022 / 2024 / 2026 全部存在）：

- **完赛者（含 `Lapped`）→ 数字** `1, 2, … 17`
- **未分类 → `R`**（Retired）/ `W`（Withdrawn）/ `D`（Disqualified）

```python
merged["ClassifiedPosition"] = pd.to_numeric(merged["ClassifiedPosition"], errors="coerce")
merged["FinishPosition"] = merged["ClassifiedPosition"].fillna(21)
```

一行替代正则，还顺手覆盖了一个正则抓不住的边界：2026 R1 的 STR
`Position=17` 但 `ClassifiedPosition=R`（被套圈且掉出 90% 距离，官方未分类）。

保守起见若只想打补丁，加一个分支即可：

```python
r"^(Finished|Lapped|\+\d+ Laps?)$"
```

> 这与本项目自己的做法一致：完赛判定收拢到 `src/semantics.py` 一处唯一定义，
> 而不是散在十几处各写一遍正则 —— 他的同一段正则出现在两个分支里，
> 分散的定义正是这次能长期没被发现的土壤。
